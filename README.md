# MT5 Telegram Tick Scalper

هذا المشروع هو هيكل Python غير متزامن لمراقبة ticks في MetaTrader 5، وتوليد إشارات scalping عند حركة bid أو ask بعدد نقاط محدد، ثم إرسال أوامر السوق وإدارة الخروج عبر take-profit وstop-loss قائمين على ticks. كما يوفّر لوحة تحكم Telegram مقيدة بمعرّف دردشة واحد، وإعدادًا مبدئيًا لـ Render Background Worker.

> **تنبيه مالي وتقني:** أنا لست مستشارًا ماليًا مرخصًا؛ هذا المشروع أداة برمجية لا يضمن الربح، والتداول عالي التردد أو scalping قد يؤدي إلى خسائر سريعة بسبب السبريد والانزلاق والتنفيذ الجزئي وانقطاع الاتصال. اختبره على حساب تجريبي، وأبقِ `DRY_RUN=true` حتى تتحقق من السلوك بالكامل.

## ملاحظة مهمة حول Render وMT5

مكتبة `MetaTrader5` تتصل عادةً ببرنامج MetaTrader 5 Terminal مثبتًا على الجهاز المضيف، ولذلك لا يكفي وجود حزمة Python وحدها في عامل Linux مُدار. يجب تشغيل البرنامج على مضيف متوافق يحتوي على Terminal وبيانات اعتماد الوسيط، مثل Windows VPS أو بيئة مهيأة بـ Wine، أو بناء bridge مستقل بين Render وTerminal. ملف `render.yaml` مرفق لتوثيق Background Worker، لكنه لا يضمن وحده توفير Terminal؛ تحقّق من بيئة التنفيذ قبل نشر أي مفاتيح أو تفعيل التداول الحقيقي. راجع وثائق الحزمة الرسمية ووثائق Render قبل اختيار البنية النهائية [1] [2].

## الملفات

| الملف | الوظيفة |

| `tests/test_strategy.py` | اختبارات وحدات لمنطق tick. |

## التثبيت المحلي

ثبّت Python 3.10 أو أحدث، وأنشئ بيئة افتراضية، ثم ثبّت التبعيات:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

في Windows يكون تفعيل البيئة الافتراضية عبر:

```powershell
.venv\\Scripts\\activate
```

عدّل `.env` وضع بيانات الحساب والبوت. لا ترفع `.env` إلى Git ولا ترسل token أو كلمة مرور MT5 في Telegram أو مستودع عام.

## إعدادات الاستراتيجية

القيم الافتراضية محافظة نسبيًا للتجربة وليست توصية مالية. `TRIGGER_POINTS` يحدد مقدار حركة bid أو ask المطلوبة لإشارة الدخول، بينما `TAKE_PROFIT_POINTS` و`STOP_LOSS_POINTS` يحددان الخروج. `MAX_ALLOWED_SPREAD_POINTS` يمنع الدخول عندما يتجاوز السبريد الحد، و`MAX_OPEN_POSITIONS` و`COOLDOWN_MS` يحدان من تتابع الأوامر.

| المتغير | المعنى | القيمة الافتراضية |
|---|---|---:|
| `TRADING_SYMBOLS` | الرموز المفصولة بفواصل | `EURUSD` |
| `LOT_SIZE` | حجم العقد | `0.01` |
| `TRIGGER_POINTS` | عتبة الحركة للنقطة | `1` |
| `TAKE_PROFIT_POINTS` | الربح المستهدف | `5` |
| `STOP_LOSS_POINTS` | وقف الخسارة | `10` |
| `MAX_ALLOWED_SPREAD_POINTS` | أقصى spread مسموح | `30` |
| `MAX_OPEN_POSITIONS` | أقصى عدد صفقات لهذا الـ magic number | `1` |
| `COOLDOWN_MS` | مهلة بين صفقات الرمز | `250` |
| `POLL_INTERVAL_MS` | زمن دورة القراءة | `50` |
| `DRY_RUN` | منع إرسال أوامر حقيقية | `true` |

> تفسير النقطة يعتمد على `symbol_info().point` للرمز في MT5، وليس على افتراض ثابت مثل pip. لذلك يجب اختبار الرمز والوسيط المحددين.

## تشغيل واختبار

شغّل الاختبارات قبل تشغيل أي اتصال:

```bash
pytest -q
```

ثم شغّل البرنامج:

```bash
python main.py
```

ابدأ بالترتيب التالي: استخدم حسابًا تجريبيًا، اترك `DRY_RUN=true`، تحقق من وصول `/start` و`/status`، راجع السجلات والسبريد والحجم، ثم جرّب التنفيذ الحقيقي على حجم صغير فقط بعد التحقق من Terminal واتصال الوسيط. عند تفعيل `DRY_RUN=false` تصبح دوال `order_send` قادرة على إرسال أوامر للسوق.

## أوامر Telegram

| الأمر | السلوك |
|---|---|
| `/start` | يثبت الاتصال ويعرض الأوامر. |
| `/status` | يعرض حالة الإيقاف، وضع DRY RUN، السبريد، والصفقات التابعة للـ magic number. |
| `/stop` | يمنع إشارات الدخول الجديدة، مع استمرار إدارة الصفقات المفتوحة. |
| `/resume` | يستأنف إشارات الدخول الجديدة. |
| `/closeall` | يغلق الصفقات التابعة للـ magic number عند التشغيل الحقيقي؛ في DRY RUN لا يرسل أمرًا. |
| `/set_spread 20` | يغير الحد الأقصى للسبريد في الذاكرة حتى إعادة التشغيل. |

جميع الأوامر مرفوضة ما لم يطابق `effective_chat.id` قيمة `TELEGRAM_CHAT_ID`.

## النشر كـ Render Background Worker

ارفع المشروع إلى مستودع خاص، أنشئ Background Worker من `render.yaml` أو عرّف أمر البناء والتشغيل يدويًا، ثم أضف المتغيرات السرية من لوحة Render بدل وضعها داخل المستودع. قبل تشغيل العامل، تأكد من وجود MetaTrader 5 Terminal في نفس المضيف أو استخدم bridge/موصلًا مناسبًا؛ عامل Python Linux عادي لن يوفّر Terminal تلقائيًا. إذا لم تكن بيئة MT5 متاحة على Render، استخدم Render لتشغيل API أو Telegram controller، وشغّل محرك MT5 على Windows VPS مع قناة اتصال خاصة ومصادق عليها.

## اعتبارات الاعتمادية وإدارة المخاطر

المحرك يعيد محاولة الاتصال بتأخير متزايد عند فشل MT5، ويشغّل Telegram بالتوازي مع حلقة السوق. الأوامر تستخدم `deviation` و`magic_number`، وتقوم طبقة الاستراتيجية بفحص spread قبل الدخول. مع ذلك لا يمكن للبرنامج ضمان تنفيذ السعر أو منع الانزلاق أو التعامل مع كل قواعد filling الخاصة بكل وسيط. ينبغي إضافة حدود خسارة يومية، حد أقصى للتعرض، سجل تداول دائم، ومراقبة خارجية قبل استخدامه بأموال حقيقية.

هذا المشروع يطبق خروجًا برمجيًا قائمًا على ticks؛ فإذا توقف العامل أو انقطع الاتصال فقد لا يُنفذ الخروج البرمجي. ولتقليل هذا الخطر، أضف أوامر SL/TP خادمة صالحة للوسيط بعد اختبار `stops_level` و`freeze_level`، أو استخدم broker-side risk controls. لا تفترض أن Telegram أو حلقة Python بديل عن حماية الوسيط.
